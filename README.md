# STOG-MetaMorph v2 (STOG-v2)

> Probe-guided adaptive model selection for time-series forecasting — v3 experimental protocol.
> Chronological splits · unified 21-method pool with LEAR/MSTL routing · placebo-controlled grafting.

---

## Overview

STOG-MetaMorph treats forecasting models as coordinate transformations on
spatio-temporal random fields and routes each input window to the most suitable
expert(s) using unlabeled probe features (spectral, statistical, and regime
probes) extracted from the input window itself.

This repository contains the **v3 experimental code**:

- **`src/`** — the core package: EPF data loaders with chronological split
  (`src/data/epf.py`, `split_mode="chronological"`), evaluation metrics, the
  expert zoo (`src/experts/zoo.py`), probes, dual-score router, theory
  (spectral affinity), and training utilities.
- **`runners/`** — 49 runnable experiment/analysis scripts (`run_*.py`,
  `run_router_v3.py`, `stats_layer.py`, `analysis_v3_*.py`, figure generators).

## Key v3 Results (E6, 5 EPF markets × 5 seeds, test MSE)

| Method | Test MSE (ALL) | Note |
|---|---|---|
| **STOG-Router (MetaMorph)** | **136.7** | TopK=3 probe-guided fusion over 21-method pool |
| LEAR (single expert) | 127.0 | strongest single method; auto-selected by router |
| B1-deep (best deep expert) | 158.4 | best static deep baseline |
| Oracle (per-window best) | 94.8 | lower bound of the pool |

- **LEAR enters the pool and is discovered by routing**: the probe router
  selects LEAR on **29.3%** of test windows — the single most-selected member —
  without ever being told it is the strongest expert.
- **Placebo-controlled grafting (E10)**: the routing gate beats a placebo
  (label-shuffled) gate by **−19.3% MSE, p = 1e-5**, confirming the gate
  exploits genuine input-window structure rather than selection noise.
- **E4 v4**: the restricted ("limited-version") form of Theorem 4 is
  **falsified** — a scalar regime-overlap gate is insufficient; routing must be
  dynamic and window-conditioned. This negative result motivates the router
  design.

See `docs/RESULTS.md` for the full v2→v3 changelog.

## Quick Start

Run everything from the repository root. Runners are resume-capable: they
write per-block checkpoints under `results/` and skip finished blocks on
re-run, so interrupted jobs continue where they stopped.

```bash
# 1. Generate v3 expert predictions on EPF (chronological split, 5 seeds)
python runners/run_e6_v3_preds.py

# 2. Run the v3 router over the unified 21-method pool (deep + MSTL + LEAR)
python runners/run_router_v3.py
```

Aggregated outputs land in `results/e6_v3/` (CSV summaries, selection
frequencies, TOST/MASE/Cohen's d tables) and `results/figures/`.

Other experiment families follow the same pattern (`run_e1_v3.py`,
`run_e4_v4.py`, `run_e10_v3.py`, `analysis_v3_t*.py`, …).

## Reproducing Results

- `results/`, `preds*/`, `ckpt/` and `*.npz` are **not** committed; every
  number in the paper tables is regenerated by the runners.
- All heavy runners are block-checkpointed (per market × seed), so partial
  reproduction is fine — delete the blocks you want to redo and re-run.
- Splits are chronological by default (`split_mode="chronological"` in
  `src/data/epf.py`); the legacy `seeded_shuffle` mode is kept only for
  ablation.

## Known Limitations

- **N10 shape bug in E8**: the N10 stress condition in `run_e8_full.py` has a
  tensor-shape defect; N10 numbers in E8 outputs should be treated as invalid
  pending a fix.
- **Sentinel accounting**: the sentinel (falsification-tripwire) bookkeeping in
  `analysis_v3_t1_sentinel.py` miscounts one arm; adjudication conclusions are
  unaffected but raw counts need recomputation.
- **E12 downgraded**: the E12 analysis (`run_e12_analysis.py`,
  `analysis_v3_t2_e12.py`) was downgraded from confirmatory to exploratory
  after protocol review; treat its outputs accordingly.
- EPF data files are not included; place them under the paths expected by
  `src/data/epf.py` (standard NEPJF/EPF toolbox layout).
